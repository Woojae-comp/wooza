# 콘텐츠산업 뉴스 Trend Radar — 현행 명세 (운영 기준, 2026-09-29)

이 문서는 **지금 운영 중인 파이프라인이 어떻게 동작하는가**만 적는다. 실험 경과·실패 사례·수치 이력은
[TREND_RADAR_V2.md](TREND_RADAR_V2.md), 설정값은 `trend_radar.yaml`, 결정 이력은 `registry/decision_log.jsonl`.
실행: `python -m trend_radar all` (한 번에) · `python -m trend_radar export` (평가 묶음).

## 0. 목표와 원칙

- 목표: 콘텐츠 상장기업 관련 뉴스(제목+요약)에서 **콘텐츠산업 트렌드**(작품·유통·정책·사건)를 월 단위로 탐지하고, 자본시장 이야기와 구분한다.
- 사람이 임의로 정한 값을 줄인다: 임계값은 분포(분위수·Otsu·null 분포)나 통계 기준(z 1.96)에서 정하고, 사람이 정한 값은 설정·결정 기록에 남긴다.
- LLM은 **비교·검토 계층**이다. LLM 판정은 참고 의견이며 정답·학습 라벨로 쓰지 않는다. LLM API 자동 호출 없음 (파일 업로드 방식).
- 운영 모델은 설정의 포인터(`e2.selected_run_id`)로만 바뀐다. 후보는 개발 표본 + 보관 표본을 통과하고 결정 기록이 있어야 승격.

## 1. 입력 (기본 원자료)

- 출처: '현재 콘텐츠 상장기업 시장평가 연구설계'의 공용 원자료 (`공용원자료스키마 = 2026-07-30_v9_news_dedup`). 연구 쪽 수집이 끝나면 최종본으로 교체한다.
  최신분(네이버 API 증분)은 나중에 같은 형식으로 합친다 (`전역기사ID`로 중복 제거).
- 현재: 2024-01-01 ~ 2026-09-26, 151,114행 → 기업명 실제 등장 기사만 남긴 뒤 83,211건.
- 검색구분: `회사명+주가`, `회사명+공시` 두 가지뿐 → **수집 단계부터 자본시장 기사 쪽으로 기울어 있다** (E2의 비콘텐츠 유입 문제의 근본 원인).
- 본문 없음: 제목 + 요약(약 150자)만. 분야 = 기업의 `분야목록` 합집합. 핵심 6분야(게임·음악·방송 및 영상·만화·애니메이션·캐릭터) + 연관산업.
- E0: 필수 열·스키마 버전 확인(다르면 중단), 스냅샷 ID(`ds_{마지막 기사일}_{해시}`) 고정, 데이터 품질표.

## 2. 단계

| 단계 | 운영 방식 | 산출물 |
|---|---|---|
| E0 등록 | 스키마 확인, 스냅샷, 품질 점검 | `01_data_quality.xlsx` |
| E2 관련성 | **E2.1** 약한 지도학습: 규칙 라벨 함수 → 라벨 모델 → 로지스틱 회귀(m_rel_ws_lr). 판정 = 세 투표(회귀 확률 ≥ Otsu 임계, 씨앗 층, 라벨 모델) 모두 찬성 INCLUDE / 모두 반대 EXCLUDE / 나머지 REVIEW. 방송사 출처·정치·사회 섹션 규칙은 제외 방향 투표 | `02_article_relevance.parquet` |
| E3 핵심어 사전 | 1~3그램 명사구(Kiwi), 보호 개체(작품명). 가중 로그오즈 z(운영 순위 B Half: INCLUDE 1 + REVIEW 0.5 대 EXCLUDE). 등급 CORE / EXTENDED / EMERGING / REVIEW / DROP. 시장 구문은 최대 REVIEW | `03_keyword_dictionary.csv`, 문서-용어 행렬 |
| E4.2 주제 | 제목 가중(2배) TF-IDF → **LSA 100차원 → K-means K=120** (분야 가중). 배정 신뢰도 HIGH/LOW/REJECTED(군집별 하위 5% 거부 경계), 잡음 점수·사유 코드, 하위 주제·층화 복구 규칙. NPMI·Leiden 네트워크는 해석용 | `07c_topic_registry.csv`, `07c_article_assignment.parquet`, `07c_lsa_embedding.npz` |
| E5a 키워드 신호 | 키워드 × 월 가중 문서빈도 → 신호 유형 (아래 3장). 결과는 keyword_signal (트렌드 아님) | `06a_keyword_signal.csv` |
| E5b 주제 트렌드 | 고정 모델 월별 배정(주제 × 월) → 같은 신호 규칙 → 최종 trend_type. 계보(E4.3) 포함 | `06b_topic_trend.csv`, `07d_topic_lineage.csv` |
| 화면 | 키워드 레이더(콘텐츠·자본시장 층) + '주제 트렌드' 탭 | `out/radar.html` |

기사 가중치: E4·E5 모두 판정 가중 **INCLUDE 1 / REVIEW 0.5 / EXCLUDE 0**. (H2 P(CONTENT) 곱 가중은 하류가 나빠져 불채택, 설정에 꺼 둠)

## 3. 신호 유형 규칙 (키워드·주제 공통, `e5.signal_row`)

확정 판정 = 마지막 **완전월**(불완전월 제외, 예: 2026-08). W = 가중 기사 수, 비중 = W / 월 전체 가중 기사.

| 유형 | 조건 (위에서부터 먼저 맞는 것) |
|---|---|
| Insufficient | 최근 달 W < 5 이고 최근 3개월 평균 < 5 |
| Event Spike | 최근 3개월 안 Kleinberg 버스트, 12개월 중 버스트 ≤ 2개월, 그리고 (12개월 지속 < 0.5 또는 최대 달 점유 ≥ 0.5) |
| Emerging | 좌측 절단 아님(수집 첫 3개월 미등장) · 12개월 이전 미등장 · 최근 3개월 대비 증가 ≥ 2배 · 6개월 지속 ≥ 0.5 |
| Growing | 최근 6개월 비중 / 직전 6개월 ≥ 1.3 · 12개월 지속 ≥ 0.5 · Robust Z ≥ 0 |
| Declining | 6개월 비 ≤ 0.7 · Robust Z < 0 |
| Established | 12개월 지속 ≥ 0.9 · |6개월 비 − 1| < 0.3 |
| Stable | 그 밖 |

- 민감도: p_rel 가중으로 다시 판정해 다르면 `sensitivity_flag`.
- **주제 저빈도 규칙 (연구자 확정)**: 월 판정이 Insufficient면 3개월 묶음(분기)으로 같은 규칙 재적용(`signal_resolution=quarter`, 창 길이를 기간 수로 환산), 그래도 부족하면 `Low volume`(판정 제외, 목록 유지).
- E4.2 잡음 후보 주제는 `Noise`로 트렌드 목록에서 제외.
- 보조 표시: cross_sector(최근 12개월 활성 분야 ≥ 3, 정규화 엔트로피 ≥ 0.6), entity_driven(한 기업 기사 ≥ 50%), keyword_support(주제 상위 키워드 중 E5a 상승 신호 비율).

## 4. 계보 (E4.3)

6개월 창을 3개월씩 밀며 같은 LSA 공간에서 재군집(K = 창 안 가중 10 이상 고정 주제 수) → 이웃 창 중심 코사인 연결.
연결 기준 = 서로 최선 짝인 쌍 코사인의 하위 5% 분위(현재 0.83). 시드 5개 중 과반 사건만 인정.
같은 창을 시드만 바꿔 재군집한 기준 대비 **split·merged는 무작위성과 구별되지 않아 쓰지 않고**, new·ended만 표시한다.

## 5. 검증 체계

- 정답 없음. 참고 판정 = GPT·Opus 5.5 교차 판정의 합의 (가이드 v1.1: `docs/review/annotation_guide.md`). 표본 600건(대표 400·진단 200, 개발 200·보관 400).
- 가이드 v1.1 핵심: 실적·재무·지분·자금조달 공시 = MARKET, 극장·팬 플랫폼 = 유통(포함), 콘텐츠 기업 당사자 사건 = CONTENT(EVENT_ISSUE).
- E2 후보 판정 기준(v1.1): 합의 CONTENT 유입(INCLUDE+REVIEW)이 E2.1 이상 · 합의 비콘텐츠 유입 30% 이상 감소 · 대표표본 가중 CONTENT 비중 E2.1 이상.
  보관 표본 400건은 이미 결과를 보고 해석에 썼으므로 개발자료로 본다 → 다음 후보는 새 보관 표본 필요.

## 6.5 표시 원칙 (2026-09-29 개선 검토 반영)

- 증감은 **보도 비중**의 증감이다. 화면 명칭: Growing/Declining → 보도 비중 증가/감소, Established → 지속 보도, Event Spike → 단기 집중,
  Converging → 연관어 연결 증가(산업 융합을 입증하지 않음), Spreading/분야 확산 → 관련 업종 증가/관련 기업 업종 다수(기업 업종 합집합 기준).
- Stable은 잔여 범주: `trend_note` = 방향 혼재(6개월 비는 기준을 넘었지만 Robust Z·지속 조건 불충족) / 변화 작음.
- 기업명 키워드는 탐색 조건: 키워드 레이더 A·C·D·E 목록에서 빼고 'A 기업별 보도 증가(탐색용)'에 따로 둔다. 연결 기업이 없으면 상위 기업을 '해당 없음'으로.
- 판정 근거 기사 = 판정 기간(확정월까지 최근 6개월, 부족하면 12개월) 안의 배정 기사만, HIGH·중심 유사도 순, 중복 제목 제외 (`06b_topic_evidence.csv`).
  E4.2 대표 기사는 '전체 기간 대표'로 따로 표시. 확정월 이후 기사는 근거로 쓰지 않는다.
- 키워드 역할(`keyword_role`): company / general(보고서체 일반어) / market(시세·공시) / format(방송 안내·바이라인) / entity / concept.
  general·market·format은 신호 목록과 주제 키워드 지지에서 제외(값 보존). 쉼표 나열('컴투스, 신작')은 보호 개체에서 제외(다음 E3 실행부터).
- export는 표별 출처(00_manifest), 주제 × 월 원 기사 수·W·N, 계산식, 사전(lexicon.yaml)을 함께 낸다.

## 6.6 확장 설계 (미구현): 사건·활동 기록과 기업·IP 장기 흐름

원자료를 기업명 수집 뉴스(수십만 건, 기업별 장기)로 교체한 뒤 착수한다. 현재 결과는 2024-01~2026-09 뿐이며 10년 분석이 아니다.
- 기본 단위 = **사건·활동**(출시·계약·분쟁·제재·인사·사업 진입/철수 등). 같은 사건의 여러 기사는 하나로 연결, 한 기사가 여러 사건을 다룰 수 있음.
- 기업·IP는 사건의 연결 대상. topic_id는 재학습 때 바뀌므로 영구 식별자로 쓰지 않는다. 회사 연혁과 IP 권리 이전을 추정으로 잇지 않는다.
- 최소 기록: 사건ID·유형·상태(발표/예정/실행/연기/취소/종료), 기사 발행일과 사건 발생일 분리, 기업ID·역할·유효기간, IP/작품ID·별칭, 근거 기사ID·문구, 후속·정정 연결.
- 보기: 최근 트렌드(무엇이 달라졌나) · 기업별 흐름 · IP 히스토리. 시범은 한 기업·한 IP(후보: 붉은사막, P의 거짓, 미르 IP — 새 원자료에서 기록 충분성 확인)로
  연표 품질을 확인한 뒤 확대. 자동으로 확인되지 않은 연결은 확정 히스토리로 올리지 않는다.

## 7. 알려진 한계 (개선 대상)

1. **수집 편향 (현 원자료)**: 검색어가 회사명+주가/공시라 콘텐츠 활동 기사 자체가 적다 (현 원자료 기준 CONTENT 약 7% 추정 — 교체 후 원자료에는 적용하지 않는다).
2. **E2 정밀도**: 유입 기사의 대부분이 자본시장 기사. 시장 기사를 거르면(E2.3b·E2.3c) 콘텐츠 기사도 잃고, 가중으로 낮추면 하류 신호가 약해졌다.
3. **주제의 기업 편중**: 56개 주제가 entity_driven. 주제가 '기업'으로 묶이고 '이야기'로 묶이지 않는 경우가 많다. 대표 기사에 목표주가·실적 기사나 무관 기사(예: 광고성)가 섞인다.
4. **본문 없음**: 제목+요약만이라 문맥 판단 한계 (LLM 검토에서 needs_more_context 약 10%).
5. **Emerging 거의 없음**: 고정 주제 대부분이 수집 초기부터 존재(좌측 절단). 새 주제 탐지는 계보 new에 의존.
6. **주제 번호 불안정성**: 원자료가 바뀌면 E4.2를 다시 만들어 번호가 바뀐다. 모델 버전 간 대응표 미구현.
7. **증분 미연결**: 네이버 API 최신 수집 경로와 합치는 단계 미구현.
