# 콘텐츠산업 뉴스 트렌드 레이더 설계

구현은 [TREND_RADAR.md](TREND_RADAR.md).

## 1. 최종 목적

이 시스템의 목적은 단순한 뉴스 수집이나 키워드 빈도 분석이 아니다.

뉴스 데이터를 지속적으로 분석하여 콘텐츠산업에서 나타나는 변화를 탐지하고, 다음을 구분하여 보여주는 **콘텐츠산업 Trend Radar**를 구축한다.

- 콘텐츠산업 전체 트렌드
- 분야별 트렌드
- 여러 분야에 공통으로 나타나는 트렌드
- 서로 다른 분야가 연결되는 융합 트렌드
- 새롭게 부상하거나 약화되는 트렌드
- 기존 이슈의 의미와 연결 구조가 바뀌는 구조 변화

즉, 단순히 **"무엇이 많이 언급됐는가"**가 아니라,

> 무엇이 증가하고 있는가
> 어떤 분야로 확산되고 있는가
> 무엇과 새롭게 연결되고 있는가
> 그 관계가 시간에 따라 어떻게 바뀌고 있는가

를 탐지하는 것이 핵심이다.

## 2. 전체 분석 구조

```text
뉴스 원자료 → 기사 단위 정제 → 키워드 추출 → 불용어·동의어·복합어 검토 → 키워드 빈도 및 시계열
→ 동시출현 네트워크 → 군집 분석 → 키워드 거리·유사도 → 분야별 비교 → 시간 변화 비교 → 트렌드 탐지 및 분류
```

키워드 분석 자체를 최종 결과로 보지 않는다. 키워드·네트워크·군집·거리 분석은 최종적으로 **트렌드를 탐지하기 위한 입력 지표**로 사용한다.

## 3. 기본 분석 단위

### 3.1 전체 산업 분석
전체 콘텐츠산업 트렌드를 분석할 때는 `전역기사ID` 기준으로 중복 제거한다. 동일 기사가 여러 기업 검색에서 반복 수집되더라도 한 번만 계산한다.

### 3.2 분야별 분석
분야별 분석에서는 원자료의 `전역기사ID-분야` 매핑을 유지한다. 동일 기사가 동일 분야의 여러 기업에 걸린 경우에는 해당 분야에서 한 번만 계산한다. 기준: `전역기사ID + 분야`

### 3.3 기업별 분석
필요한 경우 기업 단위 분석은 기존 원자료의 기업 매핑을 유지한다. 단, 기업별 분석은 산업 트렌드 분석과 별도 레이어로 관리한다.

## 4. 키워드 분석

기본 분석 텍스트: `제목 + 요약`. 검색어 자체는 분석 텍스트에 추가하지 않는다.

기사 제목과 요약에 실제 등장한 다음 키워드는 분석 대상으로 유지한다: 기업명, 서비스명, 플랫폼명, 주가, 공시, 투자, 실적, 정책, 기술, 콘텐츠 장르, 인물, 국가·지역.

## 5. 키워드 정제

### 5.1 불용어
불용어를 사전에 고정하지 않는다. 초기 분석 결과를 기준으로 Claude Code가 `제거 후보 / 유지 권고 / 검토 필요`로 후보를 제안한다.
판단 근거: 기사 빈도, 전체 기사 대비 등장 비중, 분야별 등장 분포, 시계열 변화, 네트워크 중심성, 실제 기사 제목 예시, 특정 이슈를 구분하는 정보량.
자동으로 제거하지 않고 사용자 승인 후 적용한다.

### 5.2 동의어·표기 통합
동일 개념이 여러 노드로 분리되는 경우 통합 후보를 제안한다 (예: NAVER ↔ 네이버, AI ↔ 인공지능, 매출 ↔ 매출액, 영업익 ↔ 영업이익). 자동 통합하지 않고 후보와 근거를 제시한다.

### 5.3 복합명사
형태소 분석 과정에서 하나의 개념이 여러 단어로 분리되는 경우 결합 후보를 제안한다 (예: 인공 + 지능, 영업 + 이익, 당기 + 순이익, 한국 + 거래소).

## 6. 기본 키워드 지표

각 키워드별로 최소: 등장 기사 수, 전체 기사 대비 비중, 총 출현 횟수, 최초 등장일, 최근 등장일, 월별·분기별·연도별 기사 수, 전기 대비 변화, 전년 동기 대비 변화.
절대 기사 수뿐 아니라 **전체 뉴스 대비 비중 변화**를 반드시 같이 본다. 전체 뉴스량 증가 때문에 특정 키워드가 증가한 것처럼 보이는 현상을 구분하기 위함이다.

## 7. 연관어 네트워크

노드: 키워드 / 노드 크기: 해당 키워드가 등장한 고유 기사 수 / 엣지: 동일 기사에서 두 키워드가 함께 등장.
주요 지표: 동시등장 기사 수, Jaccard coefficient, PMI. 단순 동시출현 빈도와 상대적인 관계 강도를 함께 본다.

## 8. 군집 분석

키워드 네트워크에 Louvain community detection을 적용하여 서로 강하게 연결된 키워드 집단을 탐지한다. 각 군집은 하나의 **이슈 묶음**으로 해석한다.
각 군집별로: 군집 ID, 대표 키워드, 키워드 수, 관련 기사 수, 주요 연결 관계, 중심 키워드, 이전 기간 대비 변화.
군집에 의미 있는 이름을 자동 확정하지 말고, 대표 키워드와 기사 예시를 바탕으로 **군집명 후보**를 제안할 수 있게 한다.

## 9. 거리·유사도 분석

화면에서 노드가 가까워 보이는 것을 실제 분석 거리로 사용하지 않는다. 기사 등장 패턴을 이용하여 별도의 유사도를 계산한다.
기본 구조: `기사 × 키워드 binary matrix`. 키워드 간 Cosine similarity, Cosine distance = 1 - Cosine similarity.
이를 활용하여: 특정 키워드와 가장 가까운 이슈, 특정 키워드와의 거리 변화, 서로 다른 분야의 이슈가 가까워지는지 여부, 기존에 떨어져 있던 이슈가 새롭게 연결되는지 여부를 확인한다.

## 10. 최종 트렌드 유형

### 10.1 콘텐츠산업 전체 트렌드
> 콘텐츠산업 전반에서 공통적으로 중요해지는 이슈는 무엇인가?

분석 기준: 전체 기사 비중, 증가율, 지속기간, 네트워크 중심성, 다수 분야에서의 등장 여부.

### 10.2 분야별 트렌드
> 게임·음악·방송·영화·만화 등 각 분야에서는 무엇이 변화하고 있는가?

각 분야에서 독립적으로 분석한다. 단순 상위 키워드가 아니라 **분야별 이슈 군집**까지 제시한다.

## 11. 분야 간 공통 트렌드
> 하나의 이슈가 여러 콘텐츠 분야에 동시에 확산되고 있는가?

**분야 확산도** = 해당 키워드가 유의미하게 등장한 분야 수 / 전체 분야 수. 단순 등장 여부보다 분야별 기사 비중과 증가 여부를 함께 고려한다.
`분야 특화 이슈 → 분야 확산 이슈 → 산업 전체 이슈`로 발전하는 과정을 확인한다.

## 12. 분야 간 융합·수렴 트렌드

공통 트렌드와 융합 트렌드는 구분한다.
- 공통 트렌드: 같은 키워드가 여러 분야에서 증가하는 현상.
- 융합 트렌드: 기존에는 관계가 약했던 분야나 이슈가 점차 가까워지는 현상.

분석 방법: 키워드 간 Cosine 거리 변화, 분야별 연관어 구조 비교, bridge keyword 탐지, 군집 간 연결 증가, 분야 간 공통 기사 증가.

## 13. 부상·성장·쇠퇴 트렌드

모든 키워드 증가를 동일한 트렌드로 처리하지 않는다.
- Emerging: 최근 등장하거나 기존 비중이 낮았지만 빠르게 증가.
- Growing: 여러 기간 연속 비중 증가.
- Established: 높은 비중을 장기간 안정적으로 유지.
- Spreading: 특정 분야에서 시작해 여러 분야로 확산.
- Converging: 다른 이슈 또는 분야와 새롭게 연결.
- Declining: 기사 비중과 네트워크 연결이 지속 감소.
- Event-driven: 특정 사건으로 단기간 기사량만 급증.

## 14. 일시적 이슈와 구조적 트렌드 구분

기사량이 급증했다고 바로 트렌드로 판정하지 않는다 (특정 기업 사고, 규제 발표, 실적 발표, 대형 M&A, 단일 작품 흥행).
함께 볼 조건: 증가 지속기간, 기사 비중 변화, 여러 분야로의 확산 여부, 연관 키워드 다양성, 군집 규모 변화, 네트워크 중심성 변화.
짧은 기간에만 급증하고 다시 소멸하면 `Event-driven spike`로 구분한다.

## 15. 구조 변화 트렌드

키워드 자체의 빈도가 크게 변하지 않더라도 **주변에 연결되는 키워드가 달라지는 경우**를 탐지한다 (Context Shift).
분석 방법: 기간별 연관어 TOP N 변화, Cosine 거리 변화, 군집 이동, 새 연결 노드 증가, 기존 연결 소멸, 중심성 변화.

## 16. 트렌드 프로파일

트렌드를 하나의 종합점수로만 표현하지 않는다. 각 트렌드마다 Trend Profile(기사량, 최근 기사비중, 증가 지속기간, 분야 확산도, 네트워크 중심성, 신규 연관어, 군집 변화, 분야 간 거리 변화)과 상태를 생성한다. 하나의 이슈가 여러 상태를 동시에 가질 수 있다.

## 17. Trend Radar 최종 화면

처음 보는 화면은 분석 지표가 아니라 **트렌드 중심**으로 구성한다.
A. 콘텐츠산업 전체 / B. 분야별 트렌드 / C. Cross-sector Trends / D. Convergence Signals / E. Emerging Signals / F. Structural Changes.
각 이슈 선택 시 기사량, 비중 변화, 분야 확산, 연관어, 군집, 대표 기사를 확인한다.

## 18. 시계열 비교

기본 비교 단위: 월, 분기, 연도. 각 기간마다 주요 키워드, 주요 군집, 신규 군집, 사라진 군집, 군집 간 연결, 분야 확산, 거리 변화를 계산한다.

## 19. 트렌드 후보 자동 탐지

분석 결과에서 트렌드 후보를 자동 추출하되, 자동으로 최종 결론을 확정하지 않는다. 탐지 근거와 제안 상태를 보여주고 사용자가 실제 기사와 분석 결과를 확인하여 최종 판단한다.

## 20. 대표 기사 연결

모든 트렌드에는 대표 기사, 최근 기사, 급증 시점의 기사, 해당 군집을 대표하는 기사를 연결한다.

## 21. 최종 산출물 구조

Trend Radar: 콘텐츠산업 전체 트렌드 / 분야별 트렌드(게임·음악·방송·영화·만화 …) / Cross-sector Trends / Convergence Signals / Emerging·Growing·Declining / Structural Changes.

## 22. 최종 구현 원칙

1. 단순 기사량 증가만으로 트렌드를 판정하지 않는다.
2. 절대 기사 수와 전체 기사 대비 비중을 함께 본다.
3. 분야별 차이를 유지한다.
4. 여러 분야에 공통적으로 나타나는 현상을 별도로 탐지한다.
5. 공통 트렌드와 융합 트렌드를 구분한다.
6. 군집과 연관어의 시간 변화도 트렌드로 본다.
7. 키워드 자체보다 관계 변화가 중요한 경우를 탐지한다.
8. 일시적 뉴스 급증과 구조적 변화를 구분한다.
9. 하나의 종합점수로 모든 트렌드를 서열화하지 않는다.
10. 각 트렌드가 왜 탐지되었는지 근거 지표를 함께 보여준다.
11. 실제 기사 원문 또는 제목을 함께 확인할 수 있게 한다.
12. 자동 분석 결과를 최종 판단으로 확정하지 않고 사용자가 검토할 수 있게 한다.

## 23. 최종 목표

1. 지금 콘텐츠산업 전체에서 무엇이 움직이고 있는가?
2. 각 분야에서는 무엇이 움직이고 있는가?
3. 여러 분야에 동시에 퍼지는 이슈는 무엇인가?
4. 서로 다른 분야가 새롭게 연결되는 지점은 어디인가?
5. 아직 크지는 않지만 빠르게 부상하는 이슈는 무엇인가?
6. 기존 핵심 이슈의 의미나 연결 구조가 바뀌고 있는가?
7. 일시적 뉴스 증가가 아니라 지속적으로 나타나는 변화는 무엇인가?

이를 한 화면에서 확인할 수 있는 **콘텐츠산업 Trend Radar** 구축을 최종 목표로 한다.
