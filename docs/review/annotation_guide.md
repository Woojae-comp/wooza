# E2 결과 검토 판정 가이드 (guide_version 1.1, 2026-09-29)

이 가이드는 **E2 관련성 판정 결과를 검토하기 위한 보조 판정 기준**이다. 여기서 나온 판정은 정답 라벨이나 학습 라벨이 아니다.
검토 결과는 연구자가 근거를 확인하고 결정 기록을 남긴 뒤에만 코드·설정 변경의 근거로 쓴다.

v1.0 → v1.1 변경 (연구자 결정, decision_log 기록)
- 콘텐츠 기업의 실적·재무·지분·자금조달 공시는 **자본시장 평가(MARKET)** 다.
- 극장·팬 플랫폼 등 콘텐츠를 이용자에게 전달하는 **유통 창구**는 콘텐츠산업 범위에 포함한다.
- 콘텐츠 기업이 당사자인 수사·소송·제재·지배구조 사건은 **사건 이슈(CONTENT, content_type = EVENT_ISSUE)** 로 담는다.
- 광고업·리워드 광고 플랫폼은 업종만으로 포함하지 않는다. 콘텐츠를 제작·유통하는 활동이 기사에 있을 때만 포함한다.
- 출력에 `content_type` 열을 추가했다.

## 1. 판단 대상

판단 대상은 "주가를 언급했는가"가 아니라 **"콘텐츠산업에 관한 실질적인 정보를 제공하는가"**다.
콘텐츠 관련성과 시장 중심 여부를 **각각** 기록한다.

콘텐츠산업 범위: 게임, 음악, 방송 및 영상, 만화(웹툰·웹소설 포함), 애니메이션, 캐릭터.
**유통 창구 포함**: 극장, OTT·방송 플랫폼, 음원·스트리밍 플랫폼, 팬 플랫폼(아티스트–팬 소통·콘텐츠 제공 서비스), 웹툰·웹소설 플랫폼, 게임 유통·퍼블리싱.

## 2. 기록 필드

| 필드 | 값 | 의미 |
|---|---|---|
| content_relevance | SUBSTANTIVE / INCIDENTAL / NONE / UNCERTAIN | 실질적 산업 정보 / 단순 언급 / 관련 정보 없음 / 자료 부족 |
| market_focus | YES / NO / UNCERTAIN | 시세·증권 평가·실적·재무가 기사의 중심인지 |
| review_class | CONTENT / MARKET / OTHER / UNRESOLVED | 비교를 위한 보조 판정 (학습 정답 아님) |
| content_type | WORK_ACTIVITY / DISTRIBUTION / POLICY / EVENT_ISSUE / NONE | CONTENT일 때 정보 유형. 그 밖에는 NONE |
| content_evidence | 입력 제목·요약에 실제로 있는 짧은 문구 | 관련성 판단 근거 |
| exclusion_evidence | 입력에 실제로 있는 짧은 문구 또는 빈 값 | 시장·일반 정치·타 업종 등 제외 의견 근거 |
| reason_short | 한 문장 | 판정 이유 |
| needs_more_context | YES / NO | 제목·요약만으로 부족하면 YES |

content_type
- **WORK_ACTIVITY**: 작품의 제작·출시·공연·발매·방영, 이용·시청·흥행 성과와 반응, 제작 계약, IP 활용
- **DISTRIBUTION**: 유통 창구(극장·OTT·플랫폼·팬 플랫폼·퍼블리싱)의 서비스·계약·통합·재편
- **POLICY**: 콘텐츠 대상 정책·규제·지원사업·저작권·방송 제도
- **EVENT_ISSUE**: 콘텐츠 기업·창작자가 당사자인 수사·소송·제재·지배구조 분쟁·사고 (기업이 협찬사·참고인으로만 스치면 해당 없음)

## 3. 자본시장 평가는 MARKET (v1.1)

다음이 기사의 중심이면 **MARKET**이다. 콘텐츠 기업이어도 같다.
- 주가·시세·목표주가·투자의견·종목 추천·테마주·관련주 나열
- **실적(매출·영업이익·적자·흑자)·재무·배당·자사주·지분 매각·유상증자·전환사채 등 공시**

실적 기사 안에 작품·신작 정보가 있을 때
- 작품 정보가 실적의 **원인·배경 설명**에 그치면(예: "신작 부재로 적자", "게임 부문 매출 감소") → MARKET. content_relevance는 INCIDENTAL.
- 작품의 **구체적 활동·성과 자체**가 별도로 제시되면(예: 출시일·계약 상대·판매량·이용자 지표) → CONTENT (WORK_ACTIVITY), market_focus YES.

## 4. review_class 정리 순서

1. 실질적인 콘텐츠 산업 정보(content_relevance = SUBSTANTIVE)가 확인되면 **CONTENT** (content_type 기록). market_focus가 YES여도 가능하다.
2. 콘텐츠 정보가 단순 언급이거나 없고, 시세·증권·실적·재무 평가가 중심이면 **MARKET**.
3. 콘텐츠 정보가 단순 언급이거나 없고, 일반 정치·사회·타 업종이 중심이면 **OTHER**.
4. 제목·요약만으로 판단하기 어려우면 **UNRESOLVED**. 추측으로 보완하지 않는다.

## 5. 혼합·경계 사례 (판정 가이드용 예시이며 실제 기사 판정 결과가 아님)

| 사례 유형 | 보조 판정 | 검토 이유 |
|---|---|---|
| 게임사 분기 매출·영업손실 공시, 원인으로 신작 부재 언급 | MARKET (INCIDENTAL) | 실적 공시가 중심, 작품 정보는 원인 설명 |
| 게임사 자회사 지분 매각·유상증자 공시 | MARKET | 자금조달·지분 거래는 자본시장 평가 |
| 신작 출시일·해외 퍼블리싱 계약 내용을 설명하며 주가 상승 보도 | CONTENT (WORK_ACTIVITY), market_focus YES | 출시·계약 정보가 구체적 |
| 작품의 실제 시청 성과·반응 변화를 설명하며 주가 하락 보도 | CONTENT (WORK_ACTIVITY), market_focus YES | 작품 성과 정보가 있음 |
| 작품명을 언급하며 '흥행 기대감에 강세'만 보도 | MARKET | 구체적 산업 정보 없이 시세 설명 |
| 극장 체인·팬 플랫폼의 서비스 개편·제휴·이용 정보 | CONTENT (DISTRIBUTION) | 유통 창구 |
| OTT 통합·플랫폼 재편, 공정위 승인 | CONTENT (DISTRIBUTION) | 유통 구조 변화 |
| 콘텐츠 지원 예산·방송 제도·저작권 정책을 다룬 정치 기사 | CONTENT (POLICY) | 정치 섹션이어도 정책 대상이 콘텐츠 산업 |
| 게임사·엔터사가 당사자인 압수수색·소송·제재 | CONTENT (EVENT_ISSUE) | 콘텐츠 기업 사건 |
| 정치 수사 기사에 게임사가 협찬사로만 등장 | OTHER | 기업이 사건 당사자가 아님 |
| 광고 대행·옥외광고 거래, 리워드 광고 플랫폼의 광고 사업 | OTHER | 업종만으로 포함하지 않음 |
| 리워드 광고 기업이 웹툰 플랫폼 광고 전담 등 콘텐츠 유통 활동을 함 | CONTENT (DISTRIBUTION) | 활동이 콘텐츠 유통 |
| 방송사 라디오 인터뷰에서 일반 정치인 발언을 전달 | OTHER | 방송사가 출처로만 등장 |
| 증시 기사 끝의 '○○TV 생방송·유튜브 다시보기' 안내 | MARKET 또는 OTHER (기사 본 내용 기준) | 정형 안내 문구는 편성 정보 아님 |
| 여러 업종 기사 제목을 묶은 목록 | 목록 전체 기준. 콘텐츠 항목이 제목 한 줄뿐이면 OTHER | 판정 단위는 기사 전체 |
| 연예인 개인 주거·자산·사생활 | OTHER | 작품·활동 정보 없음 |
| 제목·요약이 잘려 실질적 내용을 확인할 수 없음 | UNRESOLVED | 추측하지 않음 |

추가 원칙
- '혹평', '흥행', '정책' 같은 단어 하나만으로 판정하지 않고 제공된 문맥을 확인한다.
- 방송사명(YTN·SBS 등)이 있다는 이유로 일반 정치·사회 기사를 콘텐츠 기사로 포함하지 않는다.
  방송사 자체(민영화·매각·편성 변경·제작)가 주제면 CONTENT다. 단, 방송사 실적·재무 공시는 MARKET(3절).
- 기업의 업종이 아니라 **기사에 적힌 활동**으로 판단한다.

## 6. 입력 조건

- 1차 검토는 **분석 모델이 실제로 받는 제목·요약만** 사용한다. 추가 검색·기억 속 외부 사실로 보완하지 않는다.
- 원문을 추가로 확인한 판단은 연구자 검토 필드(researcher_review)에 따로 기록한다.
- 입력에는 기존 E2 판정·앵커·탐침 여부·추출 사유를 넣지 않는다.

## 7. 버전 관리

- 변경이 필요하면 guide_version을 올리고 변경 사유를 결정 기록에 남긴다.
- v1.0으로 판정한 초기 60건(batch_001·002)은 v1.0 결과로 보존한다. v1.1 기준 비교가 필요하면 같은 입력으로 다시 판정받는다.
- 보관 비교용 표본(holdout)을 본 뒤 규칙을 다시 조정하면, 그 표본은 이후 개발자료로 취급한다.
